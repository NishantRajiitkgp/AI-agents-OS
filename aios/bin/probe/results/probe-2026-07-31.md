**Result: rule attached and the pointer was followed.** The session narrated it unprompted — "its
pointer rule … directed me to `probe-nested/POINTED.md` before editing. I followed the pointer and
read that file first."

**Two caveats, and they are not small.**

*n = 1.* [P1](../../../../docs/design/02-principles.md)'s claim is not that agents never follow
procedures — it is that they follow them *unreliably*. One success shows compliance is possible.
It says nothing about the rate, and the rate is the entire question.

*Observer effect.* The root `AGENTS.md` probe file announces that an M0 adapter probe is running,
so **every session in this run knew it was being tested** — this one referred to "the M0 adapter
probe" by name before being asked anything. An agent that knows it is being watched for compliance
is the worst possible subject for a compliance measurement.

This confound does not affect the discovery results, which measure what the *tool* loads. It
affects only this test, which measures what the *agent* chooses to do.

## Findings

**1. Discovery is not immediate, and a single null reading is not conclusive.** `CLAUDEAGENTDESC`
returned `NONE` in two independent fresh sessions and then appeared in the third, roughly two
hours after the file was written. Whether the trigger is elapsed time, a window reload, or a
re-index is not established; that it changed is. This is a methodological finding first —
**every earlier `no` in this run had to be re-examined against it** — and it must be built into
the quarterly re-run as a settling period, or that re-run will manufacture false negatives.

**2. Nested `AGENTS.md` genuinely does not work in Cursor — and finding 1 makes this stronger,
not weaker.** `NESTED` was absent across all three sessions spanning more than two hours,
including one where the agent edited a file in the same directory and one where the user opened
it manually. Critically, `probe-nested/AGENTS.md` was written **in the same minute** as
`.claude/agents/aios-probe.md`. The latter was picked up after the delay; the former never was.
That accident turned the agents file into a **positive control** for the indexing-lag hypothesis,
and it rules the hypothesis out. This is the `M0-04` gate, and it fails.

**3. Cursor's own glob-scoped rules work, but attach reactively.** `CURSORGLOB` was absent in
Protocol A, **present in B** (agent read and edited the file), and **absent again in B′** (file
merely open in the editor, agent idle). So attachment is triggered by the agent working on the
path, not by editor state. Mechanism not fully isolated — in B the path also appeared in the
user's message — but the operational consequence is firm: **a glob rule is not reliably present
at the moment a task starts.** For a path-scoped *constraint*, that is late.

**4. Cursor reads all three `.claude/` subdirectories probed.** Subagent descriptions and skill
descriptions are always-on; command bodies are on-demand via the picker. The assumed asymmetry
("Cursor reads parts of `.claude/`") is confirmed and is broader than expected — `.claude/` is
substantially a *shared* location rather than a Claude-Code-only one.

**5. A behavioural probe cannot share a workspace with an announcement that probing is happening.**
The root `AGENTS.md` marker file declares the probe by name, and sessions read it. That is
harmless for measuring what a tool loads and fatal for measuring what an agent chooses to do.
**This carries directly to `M2-09`**, whose whole method is instructing an agent to defeat a gate
— an agent that knows it is an adversarial test is not the agent the control has to survive. The
adversarial validation must not telegraph itself.

**6. The always-on set is much larger than `AGENTS.md`.** Measured: root `AGENTS.md` + every
`alwaysApply` rule + every skill description + every subagent description. `ADR-003`'s 150-line
budget is written against `AGENTS.md` alone and so caps one input while four others grow
unwatched.

## Consequences for the adapter layer

**The D-001 gate fails, exactly as the roadmap warned.** `03 §3.2` calls nested `AGENTS.md` "the
portable path-scoping primitive" and concludes that `.cursor/rules/*.mdc` "is the *wrong* place"
for path-scoped rules, with `.cursor/rules/` "expected to stay nearly empty". Measurement inverts
both halves: the portable primitive does nothing in Cursor, and the mechanism the design rejected
is the one that works. `.cursor/rules/` cannot stay near-empty.
[D-001](../../../../docs/design/10-decision-register.md#d-001--tool-agnostic-core-with-thin-adapters)
must be reopened before M1 builds anything that depends on it — which is precisely the trigger
[11 — M0 §2](../../../../docs/design/11-implementation-roadmap.md) specifies.

**`03 §3.6` is correct after all, and my provisional reading was wrong.** It places `explorer` and
`verifier` in `.claude/agents/`, and Cursor *does* read that location — the earlier `no` was the
indexing lag in finding 1. `M4-01` and `M4-02` can use the documented home. The provisional block
below is left in place unedited as the record of a wrong call and how it was caught.

**`ADR-003`'s budget needs redefining, not renumbering.** The number was never the issue; the
denominator was. The budget must cover the measured always-on set — root `AGENTS.md` plus
`alwaysApply` rules plus skill descriptions — or it constrains one input while three others grow
unwatched.

**`ADR-007`'s premise is falsified and it needs superseding.** It deferred the whole `.claude/`
tree on the grounds that a single-tool setup could not verify it. All three probed subdirectories
turned out to be verifiable *and* read by Cursor. `.claude/` is not a dormant adapter for an absent
tool — it is live, and it is where the two subagents belong.

## Confounds — all closed

- **User-opened versus agent-opened.** Closed by Protocol B′. `NESTED` is `NONE` either way.
- **Indexing lag.** Closed by the positive control in finding 2 — a file written in the same
  minute was picked up, and the nested `AGENTS.md` was not.
- **Rejected file format.** Closed: Cursor listed the skill, the command, and the subagent, so all
  four schemas parse.
- **Stale session / context eviction.** Closed: every protocol used a fresh session with the
  question as the first turn.
